Building Modern UIs with CSS

Published on June 15, 2026

Modern CSS has grown from a simple styling language into a real design tool. The same skills that built this portfolio — Flexbox, Grid, custom properties, gradients, and smooth transitions — are enough to create interfaces that look polished and feel responsive, with no JavaScript at all. Here are the techniques I use most.

Start with the right layout system

Flexbox is perfect for one-dimensional layouts: navigation bars, button groups, or lining up an image next to text. Grid shines when you need both rows and columns, like a card grid that reflows automatically. In practice I use Flexbox for small components and Grid for whole pages, and I always let the layout system handle alignment and spacing with gap instead of relying on margins everywhere.

Keep your styles consistent with CSS variables

Custom properties let you define a design token once and reuse it everywhere. Declare your brand colors and spacing in :root, then reference them throughout your stylesheet. Change a single value and the whole site updates — that is exactly how the purple and pink palette of this website stays consistent.

Add depth with gradients and transitions

A linear-gradient background and a subtle transform on hover cost almost nothing but make an interface feel alive. Small touches like transition: all 0.3s, a gentle translateY(-3px) lift, and a soft box-shadow are the difference between a flat layout and one that feels carefully crafted.

Design for every screen, not just the big one

Use a max-width container, fluid images with object-fit: cover, and media queries to stack columns on smaller screens. Test constantly on a phone-sized viewport. If a page scrolls horizontally, something is wrong — that is usually a fixed width or an overflowing element that needs max-width: 100%.

Ship clean, readable CSS

Comment your major sections, group related rules, and avoid repeating yourself. Cleaner stylesheets are easier to maintain and make it far simpler to keep a growing project consistent.

You do not need a heavy design system to build beautiful interfaces. Master the modern CSS features, stay consistent, and let the design speak for itself.

JavaScript Performance Tips

Published on May 28, 2026

Performance is part of the user experience. A page that feels slow — or a button that stutters — loses trust even when the features are good. Over the years I have collected a few JavaScript habits that keep my code fast without making it complicated.

Debounce and throttle expensive events

Events like scroll, resize, and input fire dozens of times per second. If a handler does heavy work on every single call, the page will lag. Debouncing waits until the user has stopped, while throttling limits how often a handler can run. Both are small to implement and instantly smooth out common interaction problems.

Use event delegation

Instead of attaching a listener to every list item, attach one listener to the parent and read event.target to find out which child was clicked. You write less code, and it keeps working for elements added to the DOM later — exactly how the Read More links on this page are wired up.

Batch your DOM reads and writes

Reading and writing the DOM in alternation forces the browser to recalculate layout repeatedly — this is known as layout thrashing. Batch all reads together, then all writes, and use requestAnimationFrame for animation work so the browser can decide the best moment to paint.

Only load what you need

Big libraries slow down first load. Use defer or async on scripts, split code so the browser loads only the parts the current page needs, and lazy-load images below the fold. Every byte you do not ship is a byte the user does not have to download.

Measure before you optimize

Open the DevTools Performance tab or run Lighthouse, find the real bottleneck, and fix that. Blindly micro-optimizing rarely helps. Fast code comes from a few good habits applied consistently, not from tricks.

Performance is a habit. Start with these techniques, measure the result, and your JavaScript will feel quick on any device.

Getting Started with React

Published on May 10, 2026

React is a JavaScript library for building user interfaces out of small, reusable pieces called components. Instead of rewriting the same markup over and over, you build a component once and use it wherever you need it. It is my favorite way to build interactive web applications.

Think in components

A page in React is a tree of components. A blog card, a navbar, a button — each one is a function that returns what it should render. This makes the interface easy to reason about: fix a component, and every place that uses it gets the fix.

JSX, HTML that lives in JavaScript

React components return JSX, a syntax that looks like HTML but lives right inside your JavaScript. You can embed values with curly braces and even call JavaScript directly inside the markup. It feels a little strange at first, and then it feels natural.

Props send data down

Components receive read-only data called props. You can pass a title, a color, or a whole object, and the component renders it. Because data flows down the tree, the behavior of a component stays predictable.

State and hooks make things interactive

When a component needs to change over time — a counter, a form input, an open menu — it uses state. Hooks like useState and useEffect let function components remember values and respond to changes. This is where React starts to feel powerful.

Build something small

Start with a tiny project: a to-do list, a card layout, or a simple calculator. Sketch the component tree first, then implement it piece by piece. You will learn more from one small app than from a month of tutorials.

React rewards a simple mental model: components, props, and state. Master those three ideas and you already understand most of the library.
